- (decision) AD-1 Paradigm: Layered monolith with in-process background workers. Single Express process hosts REST API, Vite middleware (dev) or static files (prod), and all background services via setInterval. Binds: no microservice splits in v1. Prevents: building services that assume separate processes or external queues for core flows.
- (decision) AD-2 Stack (ADOPTED): Node.js + Express + TypeScript (ESM) / React 18 + Vite + Wouter / PostgreSQL (Neon serverless) / Drizzle ORM. Ratified from codebase — not re-decided here.
- (decision) AD-3 Storage boundary: All persistence goes through the IStorage interface (server/storage.ts). Services never write directly to the DB. Binds: any new service must take IStorage as a constructor arg. Prevents: two services owning the same table with conflicting write paths.
- (decision) AD-4 User scoping: Every DB query carrying user data must be scoped by userId. No cross-user reads except the getAllUsers() admin path used by background fan-out. Prevents: data leakage between tenants.
- (decision) AD-5 Calendar event identity: externalId stored with source prefix — gcal_ (Google Calendar), outlook_ (Outlook), calendly_ (Calendly). Prefix is authoritative for routing delete/update calls back to the correct provider. Prevents: ambiguous externalId collisions across providers.
- (decision) AD-6 Email dispatch: Emails are never sent inline from request handlers. All outbound email goes through the emailJobs queue table; the email-queue service polls and sends. Binds: new email types must create an emailJobs row, not call the email service directly. Prevents: double-sends on retry and lost emails on handler crash.
- (decision) AD-7 OAuth tokens: Integration credentials (access_token, refresh_token) live only in the integrations table. Never copied into user.settings or passed in API responses. Prevents: token leakage to client.
- (decision) AD-8 Company Intelligence boundary: All external research (web scraping, LLM enrichment, news APIs) must route through a single CompanyIntelligenceService. No feature or background service calls an LLM or external data API directly. Binds: the service is the single cache + rate-limit enforcement point. Prevents: redundant API calls and cost explosion.
- (decision) AD-9 Intelligence caching: Company research results cached in DB for 24 hours keyed by normalized company name + domain. Cache miss triggers async enrichment; stale-while-revalidate pattern. Prevents: duplicate LLM calls for same company across users.
- (decision) AD-10 Background scheduler: All recurring work uses in-process setInterval fan-out pattern established by calendar-scanner.ts and email-queue.ts. Services call getAllUsers(), filter by user settings, then process per-user. Prevents: a second scheduler pattern being introduced (e.g. cron jobs, BullMQ) before an explicit upgrade decision.
- (decision) AD-11 Qualification flow: calendar scan -> meeting created (status=pending) -> QualificationEngine.qualifyMeeting() called inline -> status updated. Intelligence enrichment must complete before qualification runs. Prevents: qualifying a meeting with empty company data.
- (decision) AD-12 API surface: REST only, no GraphQL. All routes registered in server/routes.ts. No routes defined in service files. Prevents: hidden endpoints that bypass isAuthenticated middleware.
- (decision) AD-13 Auth: Replit OIDC in production; local-dev bypass (auto-auth as local-dev-user-123) when REPLIT_DOMAINS env var is absent. isAuthenticated middleware is the only auth gate — no role-based access yet. Deferred: subscription tier enforcement (Stripe).
